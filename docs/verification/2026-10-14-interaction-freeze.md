# 返回与取消后的交互卡住排查（2026-10-14）

用户报告：iPhone 上条码查询一直没有结果，取消回到冰箱后无法操作；拍照、录入、购物和助手也可能出现类似表现。

本轮完成应用源码层面的审计与修复。尚未连接 iPhone 复现 UIKit 原生窗口故障，不能据此判定真实发生频率或宣称所有真机卡住都已消除。

## 范围与结论

| 范围 | 发现与处理 |
| --- | --- |
| 通用请求 / 所有业务 service | 原来没有统一截止时间，停滞的网络、凭证或响应体会让 `finally` 永不执行。普通请求默认 30 秒、AI 请求默认 90 秒；保留包装请求的 35/55 秒、学习已有 25 秒、导师已有 40 秒限制。取消主动结束等待，即使底层 fetch 没有及时结束。保留 `AbortError`，超时返回 `request_timeout`。不自动重试写入。 |
| 全应用原生弹窗 | 131 个源码文件的弹窗入口检查通过，均使用 AppModal/TabModal。此前同帧切换或等一帧仍可能与 iOS 原生关闭冲突。公共层在 layout cleanup 登记关闭，下一次呈现等 `onDismiss`；卸载导致事件缺失时，1 秒后解除呈现等待。隐藏/撤销的排队弹窗不会再次打开。安全区和 Tab 草稿保留不变。 |
| 拍照 / 相册 / 条码 | 原来退出后旧结果仍会调用父页面推进流程。现在退出、切换模式、切 Tab、卸载都会取消旧操作；压缩、相册、查条码和后续 preset/AI 补全均检查同一信号。隐藏相机不渲染 CameraView，重新激活重置扫描锁和阶段。 |
| 冰箱与购物识别核对 | 预设查找和 AI 补全传递相机取消信号，旧结果不能重新打开核对层。购物条码继续表单不再用固定 350ms 计时器，交接由公共弹窗层负责。 |
| 手动入库 / 编辑 / 购物表单 | 建议读取、生成、包装判断和图片准备在退出/改名时取消。已发出的业务写入仍按原业务语义完成；旧表单会话的响应不能关闭重新打开的草稿。 |
| 添加方式选择窗 | 关闭动画只在 `finished=true` 时卸载会留下透明遮罩。增加有界退出兜底，使用最新回调引用，父页面重渲染不重复启动退出动画。 |
| 库存详情 | 修改数量后原来先把抽屉滑出屏幕，再等待网络，期间透明原生窗口仍拦触。现在数量写入时保留可见抽屉和加载反馈，成功后关闭；失败/超时恢复操作，不允许保存时再打开移除确认。 |
| 冰箱助手 / 学堂导师 | 助手消息退出时取消网络/授权等待并释放 busy；导师已有取消信号，经统一客户端现在能中断授权等待。历史恢复、动作确认/取消等也受统一网络截止时间保护。 |
| 学堂主流程 | 现有返回路径通过 requestId 忽略旧 UI 响应，gateway 保存首答和请求键以恢复不确定提交。本轮保留该契约；相关 30 项导航和 gateway 回归通过。 |
| 共享 / 恢复 / 通知 / 个人页 / 成就 | 检查弹窗、pending/loading 和返回路径，均受到统一弹窗交接和请求截止保护。成功 mutation 的服务器效力与缓存同步规则保持原样。 |
| 首页导航转场 | 全屏拦触遮罩原来依赖动画回调释放。加入转场 2 秒、首页聚焦 5 秒恢复路径，恢复透明度、缩放和导航锁。 |

网络慢可能是触发条件；客户端缺少超时、取消与弹窗交接保障是可确定的代码缺口。原生窗口故障与发生概率仍须真机确认。

## iPhone 验收矩阵

在装有本次客户端代码的开发/预览构建执行，每条至少连续重复 10 次，并覆盖弱网和飞行模式。

1. 扫条码开始查询，立即取消；冰箱卡片、滚动、底栏必须可操作。等待超过旧请求返回时间，不得弹出旧核对页。
2. 同一操作取消后立即再次打开相机，扫描锁和加载状态必须重置。
3. 条码查询完成但 AI 补全仍未完成时取消；不得出现旧核对页或无调用者的授权弹窗。
4. 拍照识别、打开相册后取消、AI 建议生成中返回；冰箱与购物分别执行。
5. 手动表单请求包装建议后取消，再打开新草稿；旧建议和保存结果不得覆盖新草稿。
6. 新建分类生成中取消；再次打开能输入和发起新操作。
7. 助手/导师发送中退出、授权选择中退出；返回页面可操作，重新进入不能永久 busy。
8. 改库存数量后关闭：请求未完成时抽屉保持可见；网络超时后恢复操作并提示错误。
9. 录入方式选择→相机→核对→表单快速来回；通知/个人设置、成果详情、共享流程同样验证返回和重新打开。
10. 首页转场时切后台再恢复；不能残留透明全屏遮罩。

取消是终止客户端等待和后续页面推进，不代表服务端已经收到的写入或供应商处理能回滚。超时后应通过现有列表/历史/游标刷新确认真实结果，不自动重复提交。
