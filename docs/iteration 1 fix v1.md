## 1. 背景

Iteration 1 用户测试和录屏反馈暴露了以下问题：

1. 打开库存详情和保存库存修改耗时较长，界面长时间停留在同一状态。
2. 部分请求没有明确加载反馈，用户无法判断系统是否仍在工作。
3. 编辑保存成功后仍停留在详情弹窗，需要用户再次关闭。
4. 详情弹窗的 Close/Cancel 偶尔无法点击，顶部拖拽把手也曾出现无法选中或不居中的情况。
5. 冰箱顶部筛选栏缺少固定的“全部”入口，新用户也不容易发现右侧还有更多筛选项。
6. 库存输入只具备基础格式验证，极端数量或无法识别的名称仍可能进入提交链路。测试中超过一亿的数量导致系统卡顿。
7. 异常数据的二次确认弹窗信息层级松散、占用空间较大，窄屏下操作按钮拥挤。

## 2. 数据加载与保存性能

### 原因

- 保存库存时同步等待外部 Push 投递，外部网络延迟被包含在用户保存时间内。
- Realtime、保存后刷新和手动刷新可能重复请求完整库存快照。
- 打开详情弹窗时必须等待单批次详情请求完成后才显示主要内容。
- 保存或关闭详情时等待完整库存列表重新加载。
- 完整编辑即使补货规则没有变化，也会额外发送一次 mutation。

### 修复

- 共享站内通知仍在保存响应前可靠写入；外部 Push 在 Vercel 环境通过 `waitUntil` 延后执行，不再阻塞保存响应。
- 相同时间发生的库存快照请求复用同一个在途 Promise，避免重复下载。
- 库存列表快照现在包含详情首屏需要的数据。用户点击库存卡片后立即展示快照，再在后台校准最新详情与版本。
- 新增、编辑和数量调整成功后，完整列表对账改为后台执行，不再延长表单的保存或关闭状态。
- 补货规则未变化时跳过额外 mutation。

## 3. 加载状态反馈

- 通用 API 请求层增加活动请求计数。
- App 在发生网络请求时提供统一加载反馈。
- 冰箱初次加载、手动刷新、后台同步和详情读取保留各自对应的加载状态。
- 后台库存对账在页面标题区域显示轻量活动指示，不阻塞用户继续操作。

## 4. 库存详情与编辑流程

- 编辑保存成功后直接关闭整个详情弹窗。
- 冰箱页面显示“修改已保存 / Changes saved”成功提示。
- 数量修改成功后，详情弹窗不再等待完整列表刷新才关闭。
- 保存失败时保留用户输入并显示错误，弹窗恢复为可操作状态。

## 5. Close、Cancel 与拖拽手势

### 原因

顶部透明拖拽层曾覆盖过宽并抢占点击事件，导致 Close/Cancel 偶发无响应。后续将手势改为只在移动后接管时，又造成部分设备无法稳定取得 responder。

### 修复

- 拖拽事件仅注册在顶部居中的把手热区，不再覆盖整个弹窗宽度。
- 热区按实际屏幕宽度计算居中位置，避免百分比绝对定位和缩放组合产生偏移。
- 把手按下时立即接管拖拽，恢复稳定的上拉、下拉和关闭手势。
- 把手热区与左侧 Close/Cancel 保持分离。
- Cancel 按钮增加额外点击范围。

## 6. 冰箱顶部筛选栏

- 在筛选栏最左侧增加固定的“全部 / All”按钮，该按钮不会随右侧筛选项滚动。
- 点击“全部”会清除储藏状态筛选、左侧食材分类和搜索词，恢复完整库存列表。
- 右侧冷藏、冷冻、常温、过期、快过期和需补货继续使用横向滑动交互。
- 首次使用时显示“向左滑查看更多 / Swipe for more”提示。
- 用户第一次拖动筛选栏后提示自动消失，并通过 AsyncStorage 记录，后续不重复打扰。

## 7. 库存输入合法性

### 硬性限制

以下规则不可通过二次确认绕过：

- 新增、完整编辑和快捷数量修改均要求数量小于 `1000`。
- 补货最低数量和目标数量必须小于 `1000`。
- 食材名称最多 `120` 个字符。
- 单位必须来自：`item`、`g`、`kg`、`ml`、`L`、`bag`、`bottle`、`box`。
- 原有正数、价格、日期、分类、储藏方式和补货目标关系校验继续保留。

硬性限制同时存在于前端、Express API 和 Supabase 数据库，防止旧版客户端或直接 API 请求绕过保护。

### 二次确认

以下数据仍允许保存，但提交前必须由用户确认：

- `item`、`bag`、`bottle`、`box` 数量达到 `100`。
- `kg`、`L` 数量达到 `50`。
- `g`、`ml` 数量达到 `900`。
- 输入名称没有匹配到现有食材参考库。

二次确认覆盖新增库存、完整编辑和详情页快捷数量修改。用户可以选择返回检查，或确认本次数据后继续保存。

## 8. 二次确认弹窗视觉优化

- 缩小弹窗最大宽度和整体高度，移除大块无意义留白。
- 将警告图标、标题和说明合并为紧凑的信息头部。
- 每条异常原因改为独立、易扫描的提示行。
- “确认并保存”使用整行主操作按钮，并增加确认图标。
- “返回检查”调整为下方次级操作，避免两个长按钮在窄屏横向拥挤。
- 缩短中英文说明文案，改善小屏幕和长语言显示。
