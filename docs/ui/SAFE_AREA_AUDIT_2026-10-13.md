# iPhone 顶部安全区检查（2026-10-13）

检查所有主页面、子页面、原生弹窗、展开抽屉和悬浮入口。实现依据 [Expo SDK 57 安全区文档](https://docs.expo.dev/versions/v57.0.0/sdk/safe-area-context/)。

| 区域 | 检查结果与处理 |
| --- | --- |
| Home | 通知入口和保鲜信息改为实际 inset 定位；悬浮 Spoonie 的可见区域裁切在状态栏下方，保留原有窗口坐标和拖拽状态。 |
| Cart | 主列表、补货列表、Checkout review、库存预览改为实际顶部 inset；手动新增/编辑面板在键盘容器中预留安全区。 |
| Fridge | 主列表、助手聊天页改为实际顶部 inset；详情抽屉展开高度受顶部安全区限制；快捷消耗面板按键盘缩小后的可用高度扣除上下安全区。 |
| 录入与识别 | 库存录入、照片/条码相机、条码核对、识别核对去掉固定状态栏估值；嵌入详情抽屉的录入表单不重复加顶部留白。 |
| Learn | 首页、课程、资源、练习、测验、结果复用 `LearningPage` 的原生 SafeAreaView；AI 问答同样使用原生 SafeAreaView；视频及加载共用单个弹窗并由公共组件提供安全区容器。 |
| Wins | 成就首页、详情、里程碑、解锁展示、勋章墙已有实际 inset 布局；原生弹窗统一接入公共安全区容器。 |
| Me | 主页面和加载骨架改为实际 inset；通知、语言、恢复、隐私、重放引导共用抽屉按实际 inset 限制展开高度，并限制上拉回弹的绘制位置；昵称编辑键盘容器预留安全区。 |
| 共享 | 冰箱菜单随顶部 inset 定位；创建、成员、邀请、加入、扫码共用全屏流程按实际 inset 留白。 |
| 引导与隐私 | 首次引导去掉固定 54px；隐私同意原生 SafeAreaView 接入弹窗内部 provider。 |
| 小型居中弹窗 | 删除确认、分类创建、日期/时间选择、徽章按住详情没有贴顶操作栏；检查其居中/底部布局并统一弹窗 provider。 |

`AppModal` 在每个原生 Modal 内放置 SafeAreaProvider，覆盖原先 11 个直接使用原生 Modal 的组件。`TabModal` 复用同一实现并保留所属 Tab 的可见性门控。Provider 只测量安全区，不自动添加 padding；主窗口仍用 initialWindowMetrics，弹窗不强行复用主窗口初始尺寸。

验证：

- TypeScript 全量类型检查通过。
- 安全区回归：独立弹窗 provider、参数透传、全局与 Tab 弹窗可见性、127 个应用源码文件的原生 Modal 导入审计、不同 inset 下设置抽屉强力上拉不越界。
- 库存录入/结账回归覆盖 0、44、59、62 顶部 inset，包含嵌入模式不重复留白；原有表单数据保留测试通过。
- Learn 视频重复播放、关闭加载后重开、学习流程和网关，以及库存快捷消耗逻辑回归通过。
- 开发 Learn 画布新增 `safeTop=0|44|59|62` 参数；仅用于开发预览，生产页面从设备读取 inset。

本轮浏览器工具安全策略拒绝读取本地预览，因此没有新增截图验证。未连接 iPhone；上述代码与自动化检查不替代真机核对。安装包含这些改动的新包后，需重点复核灵动岛设备的 AI 问答、相机、展开抽屉、键盘弹出和共享扫码。

本轮只调整 UI 布局和弹窗容器，没有修改数据库、API 数据契约或库存写入行为。
